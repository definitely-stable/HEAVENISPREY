# ADR-009 — P0-01: первая атака героя, жизненный цикл врагов, расталкивание, порядок смерти, игровые ассеты

- **Status:** ACCEPTED — решения по делегированию владельца проекта (2026-11-13: открытые архитектурные и геймплейные вопросы передать на независимую консультацию «для лучшего решения»). Числа в §1–§3 проверены на черновом целочисленном прототипе поверх `tools/content/fx.py` и `hip_rng.py`; окончательно фиксируются golden-векторами и бот-логами соответствующих срезов.
- **Date:** 2026-11-13
- **Scope:** симуляция P0-01 после среза P0-01E ([ADR-008](ADR-008-sim-numeric-model.md) `hip-fx-v1`): автоатака `skill.spirit_sword`, смерть и слоты врагов, снаряды, темп спавна, расталкивание, placeholder-базы, порядок терминальных событий тика (часть GAP-PRECEDENCE), хранение бинарных ассетов `game/`, порядок срезов.
- **Не делает:** не меняет каталоги v7 (правки каталога ниже — рекомендации для отдельных контентных PR), не вводит статусный движок, XP, выбор улучшений и арт — это отдельные срезы.

## 1. Первая атака героя: `skill.spirit_sword`, часть `damage`

Канон уже решает: кулдаун — аккумулятор ([ADR-008:64](ADR-008-sim-numeric-model.md)); слоты — «спавн занимает наименьший свободный слот; уплотнения и swap-remove нет», пересечение `(dx²+dy²) ≤ (r1+r2)²` (ADR-008:55); один экземпляр атаки бьёт цель не более одного раза ([enemy-threat-contract:8](../spec/v7/enemy-threat-contract.md)); `pending_death` и kill ровно один раз на поколение ([s09:41](../spec/core/s09.md)); тай-брейк целей `(distance², id)` ([v5_semantics:55](../spec/v5/v5_semantics.md)).

**Кулдаун.** `period_mt = base_cooldown_ticks × 1000 = 50000` ([skills.json](../config/v7/skills.json)), `rate_fx = 1000`, `skill_acc` с 0. Каждый тик `skill_acc += rate_fx`; при `skill_acc ≥ period_mt` и наличии цели — каст и `skill_acc −= period_mt`; без цели — `skill_acc = period_mt` (готов, заряды не копятся). Не более одного каста за тик.

**Цель.** Живые враги с `d² ≤ range²` от центра героя (граница включительно), `range = 384000 su` (8 клеток = минимальная дистанция спавна). Минимум `d²`, при равенстве меньший слот. RNG не расходуется.

**Снаряд.** Появляется в позиции героя после его хода. Направление `Fx.normalize_q14(target − hero)`, нулевой вектор → `(16384, 0)`. Скорость `Fx.mul_q14(12000, dir)` (720 px/с, 2.5 скорости героя), радиус 10000 su, `ttl = 40` тиков (480 px), `pierce = 1` (до двух разных целей), без самонаведения. Центр вышел за прямоугольник арены после шага → снаряд удаляется в этот тик без проверки попаданий, отскока нет. Конфигурация невалидна, если `speed > radius + min(kind_radius)` (защита от туннелирования). `MAX_PROJECTILES = 64`; нет свободного слота — каст удерживается.

**Урон.** `SKILL_BASE_DAMAGE_MHP = 10000` (placeholder), фиксируется в снаряде при касте. Минимальный урон попадания `maxi(1, damage)` mhp при базе > 0 (закрывает пункт ADR-008:66). Будущие модификаторы — группы `Fx.mul_hp` по ADR-008, не произведение множителей.

**Hit ledger.** У снаряда `pierce + 1` ячеек `enemy_uid` (0 = пусто). За тик снаряд выбирает среди живых пересекающихся врагов, которых нет в ledger, ближайшего к своему центру (`d²`, затем слот), наносит урон, пишет uid; при `pierce_left = 0` удаляется, иначе `pierce_left −= 1` и выбор повторяется. Враг с `hp ≤ 0` получает `hp = 0` и исключается из всех дальнейших проверок тика: второй снаряд по нему не тратит пробитие, kill — один.

**Идентичность и слоты.** Массив `enemy_uid` (монотонный `next_enemy_uid` с 1; `uid = 0` — свободный слот, остальные поля слота 0). Массивы не укорачиваются; лимит спавна считает `enemy_alive`. Digest: заголовок (прежние поля + `next_enemy_uid`, `enemy_alive`, `kills`, `skill_acc`, `spawn_acc`, число слотов снарядов), затем все слоты врагов `[uid, kind, x, y, hp, cooldown]`, затем слоты снарядов `[x, y, vx, vy, ttl, pierce_left, damage, ledger…]`; свободные слоты — нулями. Presentation интерполирует врага только при совпадении uid в тиках N−1 и N.

**`status.mark` отложен** до статусного движка: у метки в [statuses.json](../config/v7/statuses.json) нет длительности, эффекта и потребителя. `apply_status:status.mark` перечисляется как неисполняемая операция.

**Порядок фаз тика** (в скобках фаза [s04](../spec/core/s04.md)): 0 завершённый забег не шагает → 1 команды → 2 ход героя и clamp (s04-2) → 3 спавн ≤ 1 в наименьший свободный слот → 4 преследование, позже расталкивание (s04-2) → 5 готовность навыка, цель, каст (s04-3) → 6 шаг снарядов, выход за арену удаляет (s04-4) → 7 попадания: снаряды героя по слотам, затем контакт врагов по слотам; враг с `hp = 0` не бьёт (s04-5) → 8 смерти: враги по слотам (слот обнуляется, `kills += 1`), снаряды с `ttl = 0`, герой (`hp ≤ 0` → `hp = 0`, run over) (s04-8) → 9 `tick += 1`. Смена порядка фаз → `sim_schema_version = 3` ([ADR-007:227](ADR-007-runtime-bootstrap.md)).

Удары героя раньше контакта: убитый в тике враг не кусает (согласовано с `pending_death`). Пробитие награждает выстраивание врагов; дальность = дистанция спавна позволяет снять волка до укуса.

## 2. Расталкивание врагов

Отдельный срез сразу после автоатаки (`sim_schema_version = 4`); канон: двухфазно, сетка `floor_div(x, cell_su)`, без `Dictionary` (ADR-008:55), без попарного O(N²) ([s11:16](../spec/core/s11.md)).

1. Преследование пишет предварительные `tx, ty` без clamp; касающийся героя враг стоит.
2. Сетка `cell_su = 2 × max(kind_radius)`, индекс зажат в границы; раскладка счётной сортировкой по слотам (плоские `cell_start`, `cell_items`), свободные слоты пропускаются.
3. Пары: клетки построчно; соседи (0,0) только `j > i`, затем (+1,0), (−1,+1), (0,+1), (+1,+1). При `d² < (ri+rj)²`: `d = Fx.isqrt(d²)`, `half = (ri + rj − d) >> 1`, `hx = sign(dx)·floor_div(|dx|·half, d)` (так же `hy`), `push_i += h`, `push_j −= h`; при `d² = 0` толчок по x на `(ri+rj) >> 1`, плюс большему слоту. Позиции в проходе не меняются.
4. Бюджет `SEP_MAX_CHECKS = 4096` проверок пар за тик; остаток — в следующих тиках.
5. Применение по слотам: `m = (tx − x, ty − y) + push`; при `|m|² > speed²` → `m = Fx.mul_q14(speed, Fx.normalize_q14(m))`; затем clamp в арену. Инвариант: за тик враг не сдвигается дальше своей скорости, расчёты телеграфов GAME-ARCH-02 сохраняются. Герой не толкается.

Приёмка среза включает p95 тика ≤ 4 мс при 150 врагах headless ([s24:18](../spec/core/s24.md)); стоимость в GDScript до этого не измерена (оценка 1.5–2.5 мс), поэтому лимит врагов до стресс-фикстуры — 48.

## 4. Порядок терминальных событий тика (часть GAP-PRECEDENCE)

1. Тик атомарен: все фазы доходят до конца, HP героя внутри тика может уйти в минус; смерть героя проверяется один раз, в фазе смертей, после смертей врагов.
2. Порядок фаз событий `combat → death → drop → pickup → poi → progression` ([game-arch-02-encounters:44](../spec/v7/game-arch-02-encounters.md)) принят; закрывает OPEN RLOOP-01 ([game-arch-00:66](../spec/v7/game-arch-00-run-orchestration.md)).
3. Внутри death: смерти врагов по слотам (включая босса) → проверка победы → воскрешение → поражение. Приоритет **победа > воскрешение > поражение**. Воскрешения в каноне нет; место зарезервировано (один заряд, событие `revive:<run_uid>:<n>`).
4. В терминальном тике фазы pickup, poi и progression не исполняются: XP в тик смерти не начисляется, «смерть и level-up в одном тике» невозможны по построению. Камни опыта на земле при смерти теряются (ответ на XP-02, [game-arch-01:104](../spec/v7/game-arch-01-xp-pickups.md)).
5. Ожидающие выборы при терминале отменяются: `RUNNING → FINISHING` минуя `CHOICE_PAUSED`, одна запись `CHOICES_VOIDED {count, uids}`, поток `offers` не расходуется, `build_revision` не меняется (game-arch-00:93).
6. События тика до фазы death (убийства, награды босса) остаются заработанными.
7. Расчёт при смерти — один раз на `run_uid`, дедупликация по `run_uid + reward_event_id` ([reward_contract.json](../config/v7/reward_contract.json)): Spirit Stones по формуле от уже зафиксированных вех, без бонуса за смерть; Dao Seals 0; тренировка и нерейтинговый custom — ничего; внутризабеговые XP, уровень и билд сгорают; выход из забега = поражение.

Остаётся открытым в GAP-PRECEDENCE: пауза против ожидающего выбора, выход во время выбора (RLOOP-03) и восстановление fail-closed — к срезу сохранений; условие победы режима и судьба BOSS_RELIC — до среза босса. До XP/level-up решить: XP-01 (рекомендация — множитель при создании дропа), таблица порогов уровней, `xp_value` врага, радиус подбора (рекомендация — 2 радиуса героя, без магнита), режим показа Immediate по умолчанию, минимальный состав предложений.

## 5. Бинарные ассеты `game/`

Git LFS, как для `ref/`; `.import` — текст в обычном git ([s17:35](../spec/core/s17.md)); ассеты не входят в `content_digest` и `rules_hash`.

```text
game/assets/**/*.png  filter=lfs diff=lfs merge=lfs -text
game/assets/**/*.webp filter=lfs diff=lfs merge=lfs -text
art_source/**         filter=lfs diff=lfs merge=lfs -text
*.import text eol=lf
```

Раскладка: `game/assets/manifest.json` (обычный git; поля [s16:34](../spec/core/s16.md) + `sha256`, `bytes`, `asset_version`, `art_bible_version`, `content_ids`), `game/assets/{characters,enemies,tiles}/<id>/<file>.png`, мастер-листы в `art_source/<asset_id>/` вне `game/`. Стабильные `asset_id` (`asset.char.hero_sword`, `asset.enemy.yin_corpse`, `asset.enemy.blood_wolf`, `asset.tile.jade_grove_floor`); имя файла без версии, версия в манифесте; presentation ищет путь по `asset_id`. Двойная плотность к окну 1280×720: кадр персонажа 192×192, тайл 96×96; герой 4 направления × 4 кадра, враги 2 × 4; без зеркалирования (свет сверху-слева, [art-bible-001](../spec/v7/art-bible-001.md)); позиция симуляции = `feet_anchor` ([s14:18](../spec/core/s14.md)); тени и свечение не запекаются. Импорт: Lossless, без mipmaps, `fix_alpha_border`, фильтр Linear, padding в TileSet. CI: `design-validation` сверяет LFS-указатели с манифестом без LFS; `godot-tests` тянет только `game/assets/**` с кэшем, `ref/` — никогда.

Приёмка первого арт-среза: LFS-объекты 1:1 с манифестом; `content_ids` существуют в v7; RGBA, прозрачное поле ≥ 2 px, стабильный `feet_anchor`; метрики паспорта (палитра ΔE ≤ 12, тона ±10 п.п., хрома пола ≤ 0.15, у героя нет цвета угрозы `#e8343c`, нет текста и теней); headless-импорт Ubuntu/Windows; digest golden-трасс одинаков со спрайтами и с кругами; скриншоты 48 врагов на 1280×720 и 3440×1440; карточка ассета ([ASSET_CARD](../templates/ASSET_CARD.md)) с якорями и хэшем промпта, генерация только утверждённой capability (AGENTS.md п. 3); объём LFS среза ≤ 10 МБ. Арт-срез запускается отдельно (AGENTS.md п. 8); это ADR фиксирует только правила хранения и приёмки.

## 6. Порядок срезов

1. **Автоатака** (§1, спавн-аккумулятор §3, `sim_schema_version` 3): паритет Python = GDScript на 18000 тиков, тесты §1 и спавна.
2. **Бот-сценарии** (стоит, по кругу, кайтер; оракул порождает лог, GUT воспроизводит): одинаковые digest, время смерти в заданных коридорах.
3. **Расталкивание и стресс-фикстура** (§2, `sim_schema_version` 4): p95 ≤ 4 мс при 150 врагах, digest 10000 тиков одинаков на Ubuntu и Windows (остаток GAP-SIM-NUMERIC).
4. **Убийства → камни XP**: ΣXP = сумма собранных, повторное начисление источника отвергается, тесты §4.
5. **Выбор при level-up** (Immediate, пауза тика): тик не растёт во время выбора, лог кайтера с улучшениями доживает до 300 с.
6. **Первый арт-проход** (§5) — параллельно с шага 3.

Обновление CURRENT_STATE и system_binding входит в закрытие каждого среза.

## Consequences

- Digest зависит от истории слотов: логически равные миры с разной «высотой» массивов дают разный хэш — корректно для replay и сохранений; сравнивать состояния только при одинаковой истории.
- Фиксированное направление снаряда и «ближайшая цель» иногда выбирают мертвеца вместо волка — осознанная простота; приоритеты целей остаются улучшениям.
- Числа баланса получены на прототипе с посредственным ботом и фиксируются бот-логами среза 2.
- Квота Git LFS: CI тянет только `game/assets/**` с кэшем.
