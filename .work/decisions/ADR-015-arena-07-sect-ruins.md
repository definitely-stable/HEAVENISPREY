# ADR-015 — арена 07 «Руины секты Юнхэ» по REF-033

- **Status:** PROPOSED; срезы А0 и А1 реализованы 2026-11-16 (А1 — по согласию владельца проекта, итог в §8). Владелец проекта 2026-11-16: карта «вообще референсу и карте не соответствует», «маленькой карту не делать». Числа сетки и баланса стартовые и уточняются плейтестом через amendment этого ADR; темп спавна в новой арене — отдельное решение (§8.5).
- **Date:** 2026-11-16
- **Scope:** топология арены `stage.jade_grove`:
  - проходимость, высоты, лестницы и мост;
  - руины вокруг печати, точки спавна и входы;
  - размер поля;
  - порядок срезов, которые переносят сетку в симуляцию и в картинку.
- **А0 не менял** симуляцию, digest, трассы, боты и сцену: он добавил сетку, валидатор и тесты. **А1** переносит сетку в симуляцию и сцену (§8): арена в игре — 76 × 71 клеток со стенами вместо прямоугольника 32 × 20 (ADR-009 §3).
- **Опирается на:**
  - [GAME-ARCH-02 §1](../spec/v7/game-arch-02-encounters.md) (`StageTopologyDef`, правила E_ISOLATED_POCKET, E_TRAP_CORRIDOR, E_SPAWN, E_ARENA_BLOCKER);
  - [ADR-014](ADR-014-art-02-isometric-light.md) (проекция 2:1, двор A3);
  - доска REF-033 из [каталога `ref/`](../../ref/README.md): план коллизий, петли движения, точки спавна, профиль высот, тайлы;
  - REF-029 и REF-056 — для облика стен, лестниц и реквизита.

## 1. Контекст

Двор A3 ([ADR-014 §11–§12](ADR-014-art-02-isometric-light.md)) — плоский пустой ромб 32 × 20 клеток. По краю у него низкие перила, а по углам расставлен мелкий реквизит. На доске REF-033 арена устроена иначе:

- двор-восьмиугольник с печатью в центре;
- кольцо руин с проходами вокруг печати;
- терраса ворот сзади, приподнятые крылья по бокам, мост и лестницы;
- жаровни, столбы и львы стоят по линиям стен;
- две петли движения (внутренняя через проходы кольца, внешняя вдоль парапета);
- шесть красных колец спавна на внешней петле.

Реквизит на краю пустого прямоугольника такой план не передаёт. Поэтому сначала нужна сама сетка, а картинку потом собирают по ней.

## 2. Решение: сетка арены

Сетку рисует генератор [`tools/content/arena_layout.py`](../../tools/content/arena_layout.py) и записывает её в [`game/content/arena/jade_grove.json`](../../game/content/arena/jade_grove.json) (до среза А1 файл лежал в `.work/proposals/arena-07-sect-ruins/topology.json`). Ключ `--check` в CI падает, если файл отличается от того, что рисует генератор.

Элементы кладутся в экранных осях проекции 2:1 относительно печати:

- u = dx − dy — вправо по экрану;
- v = dx + dy — вниз по экрану;
- задняя часть с воротами — это v < 0.

Так план совпадает с доской на экране, а не только в сетке.

| Символ | Что это | Движение | Выстрелы |
|---|---|---|---|
| `.` | пол двора | да | да |
| `H` | приподнятый пол (терраса, крылья) | да | да |
| `^` | лестница | да | да |
| `B` | мост | да | да |
| `S` | точка спавна (пол) | да | да |
| `E` | вход и старт (пол) | да | да |
| `w` | низкая стена, балюстрада, руина | нет | да |
| `#` | твёрдое: столб, статуя, колонна жаровни, здание | нет | нет |
| ` ` | пустота: обрыв, туман | нет | нет |

Высота (`H`, `^`) существует только в картинке. Симуляция остаётся плоской: по высоте не меняются ни скорость, ни урон, ни видимость. Подняться на крыло можно только по лестнице или мосту, потому что везде, где `H` касается `.`, стоит подпорная стена `w`.

**Размер.** Используемая рамка — 76 × 71 клеток по 48 px. Проходимых клеток 2181: это 3,41 поля P0 (640) при прежнем размере клетки и скорости героя 288 px/с. Валидатор не пропускает меньше 3 × 640.

**План по доске:**

- **Двор:** восьмиугольник на экране, |u| ≤ 34, |v| ≤ 30, срезанные углы.
- **Терраса ворот сзади.** Зал ворот (`#`) с лестницей шириной 11 клеток, по бокам львы.
- **Западная платформа старого клёна:** клён и святилище — `#`, на платформе есть своя лестница.
- **Мост:** с западной площадки через пустоту во двор. Западная площадка — первый вход и старт.
- **Восточная площадка** со вторым входом и своей лестницей.
- **Южная площадка** с передней лестницей.
- **Парапет** (`w`) по всему краю у пустоты, восемь столбов и обелисков вдоль него.
- **Кольцо руин вокруг печати:**
  - шесть обломков на радиусе 9,6–12,2 клетки;
  - на концах обломков столбы (`#`), в середине низкая стена (`w`);
  - проходы между обломками шире самих обломков, через них идёт внутренняя петля;
  - между обломками на радиусе 14,5 клетки стоят шесть колонн жаровен 2 × 2.
- **Круг босса:** радиус 7 клеток вокруг печати, внутри ничего блокирующего нет.
- **Точки спавна:**
  - шесть на внешней петле на радиусе 19 клеток, под углами 40°, 100°, 160°, 220°, 280°, 340° (красные кольца REF-033);
  - одна на южной площадке;
  - одна на западной платформе.
- **Без карманов.** Проходимые клетки, до которых нельзя дойти от старта (за статуями и в углах), становятся стеной.

## 3. Правила проверки

[`scripts/validate_arena_layout.py`](../../scripts/validate_arena_layout.py) использует только стандартную библиотеку. Он прогоняет сетку через `check_topology` из [GAME-ARCH-02](../spec/v7/game-arch-02-encounters.md): `w`, `#` и пустота считаются стеной. Затем он проверяет правила доски.

| Код | Правило |
|---|---|
| E_SCHEMA, E_TERRAIN | поля файла, размер строк, символы только из легенды |
| E_ISOLATED_POCKET, E_TRAP_CORRIDOR, E_SPAWN, E_ARENA_BLOCKER | правила GAME-ARCH-02 §1: нет карманов, нет коридоров шириной 1 длиннее 4, есть спавн не ближе 8 клеток, круг босса чист |
| E_HEIGHT | приподнятый пол не касается пола двора без лестницы |
| E_SIZE | проходимых клеток не меньше 3 × 640 |
| E_SPAWN_POINTS | не меньше шести точек спавна рядом с полом двора (внешняя петля) |
| E_ENTRIES | ровно два входа, они перечислены в файле, старт — один из них |
| E_SEAL_RING | руины закрывают от 30 до 70 % кольца 9,6–12,2 вокруг печати |

Текущий результат: 76 × 71 клеток, 2181 проходимая (×3,41), самый длинный коридор шириной 1 — 2 клетки, восемь точек спавна (шесть на петле), два входа, кольцо закрыто на 44 %.

[`tests/test_arena_layout.py`](../../tests/test_arena_layout.py) проверяет:

- сетка проходит все правила;
- файл совпадает с генератором, а генерация детерминирована;
- ворота сзади, первый вход далеко слева за мостом, второй справа.

Каждое правило ловит свою мутацию:

- перекрытый мост → карман;
- `H` на лестнице → нет подъёма;
- столб в круге босса;
- убранная точка спавна, испорченный вход;
- урезанное поле;
- расчищенное кольцо;
- неизвестный символ.

## 4. Что меняется в симуляции (срез А1)

В срезе А1 симуляция получает сетку как данные `StageTopologyDef` и меняет поведение так:

1. **Коллизии.** Герой и враги не входят в `w`, `#` и пустоту и скользят вдоль стены по оси, которая не заблокирована. Проверка идёт по клеткам целыми числами `hip-fx-v1`. Расталкивание тоже не выталкивает врага в стену.
2. **Навигация врагов.** Детерминированное поле потока от клетки героя (BFS по 4 соседям, пересчёт при смене клетки героя, порядок обхода фиксирован). Враги идут по полю, а не напрямую, поэтому обходят руины и поднимаются по лестницам.
3. **Спавн.** Враги появляются в точках `S` и у входов `E` на расстоянии не меньше `min_spawn_distance_cells` (8) от героя, а не на периметре прямоугольника. Выбор точки детерминирован по потоку RNG спавна.
4. **Выстрелы.** Снаряды героя и фонаря гаснут в `#` и в пустоте и пролетают над `w`. Край прямоугольника для снарядов больше не используется.
5. **Камера и границы:**
   - камера следует за героем по рамке сетки;
   - старт — первый вход;
   - круг босса — центр печати.
6. **Паритет.** Python-эталон (`sim_core.py`) повторяет коллизии, поле потока и спавн бит в бит. `sim_schema_version` повышается.
7. **Боты и баланс.** Перепривязываются коридоры времени смерти ботов, медианы и якоря `kiter_upgrades`. Темп спавна и лимиты угроз не меняются без отдельного решения.

Бюджет: поле потока на 76 × 71 = 5396 клеток считается за один BFS только при смене клетки героя. Стресс 150 врагов должен остаться в пределах 4 мс на тик p95 (как в ADR-009). Если не останется, срез А1 вводит пересчёт по частям с курсором.

## 5. Что меняется в картинке (срез А2)

Картинку собирают по той же сетке:

- **Набор деталей через утверждённый imagegen** с досками REF-033 и REF-029 (и REF-056 для руин):
  - парапет со столбиками и красными панелями;
  - подпорная стена;
  - лестница и мост;
  - зал ворот;
  - столбы и обелиски;
  - колонны жаровен;
  - львы и обломки кольца.
- **Расстановка** по клеткам `w` и `#`: стены идут ровными отрезками по линиям сетки, а не произвольными точками, как в нынешнем `ArenaDressing`.
- **Высота крыльев** рисуется подъёмом пола и боковой гранью стены. Пустота — обрыв и туман `ground_layer`.
- **Пропорции к герою:** столб — 2–3 роста героя, лев и колонна жаровни — 1,2–1,5 роста. Их проверяет валидатор ассетов.
- **Запас LFS.** Остаток бюджета 4,2 MiB учитывается в паспорте ассетов.

## 6. Срезы

| Срез | Что | Готово, когда |
|---|---|---|
| А0 (этот) | ADR, сетка, валидатор, тесты, шаг CI | сетка проходит все правила, CI зелёный |
| А1 | симуляция: коллизии, поле потока, спавн по точкам, выстрелы, паритет Python, новая версия схемы, боты | паритет трасс, стресс в бюджете, боты перепривязаны |
| А2 | картинка: набор деталей по REF-033/029, сборка по сетке, высоты, пропорции | кадр сверен с REF-033 рядом, валидатор ассетов PASS |
| А3 | реакция врагов на удар и смерть, больше направлений анимации | отдельное решение |

## 7. Последствия

- Поле больше в 3,4 раза, поэтому плотность орды при том же темпе спавна падает. Спавн из точек на петле частично это возмещает, потому что враги приходят по путям, а не со всех сторон сразу. Окончательный темп — после плейтеста среза А1.
- Боты «стоит» и «по кругу» в А1 меняют поведение: кругу мешают руины. Их сценарии перепривязываются, а не подгоняются под старый результат.
- Нынешний `ArenaDressing` с фиксированной расстановкой на 32 × 20 уходит в срезе А2.

## 8. Итог среза А1 (2026-11-16)

### 8.1. Данные

- Сетка лежит в контенте игры: [`game/content/arena/jade_grove.json`](../../game/content/arena/jade_grove.json). Генератор дописывает в файл старт (`start`, западный вход [8, 63]) и именованный реквизит на его клетках `#` (`props`: зал ворот, шесть львов, десять столбов, шесть колонн жаровен, клён).
- Симуляция читает только `rows` и `cell_px`. Конфиг забега (`SimConfig.arena`, `ArenaTopology`) добавляет в `to_ints` размер сетки, клетку, тело стены и коды клеток. Поэтому `rules_hash` и digest трасс зависят от сетки.
- `sim_schema_version` = 13, схема векторов ядра — 12, схема прогонов ботов — 5, политика ботов — 3.

### 8.2. Правила симуляции

| Правило | Как сделано |
|---|---|
| Коды клеток | `.HB^SE` — проход (0), `w` — низкая стена (1), `#`, пустота и всё за рамкой — твёрдое (2) |
| Тело у стен | квадрат с половиной стороны 18 px (`P0Tuning.WALL_BODY_PX`, placeholder) у героя и всех врагов; радиусы урона и расталкивания не меняются |
| Движение | сначала x, потом y; на каждой оси тело встаёт вплотную к первой клетке, в которую вошёл бы его передний край (скольжение вдоль стены); затем прежний зажим в рамку |
| Рывок богомола | идёт через то же движение со стенами |
| Поле потока | BFS по 4 соседям от клетки героя, порядок +x, −x, +y, −y; пересчёт только при смене клетки героя |
| Цель врага | герой, если враг в его клетке, клетка недостижима, или поле спускается к герою ровно по тем осям, по которым они разнесены; иначе центр следующей клетки поля (по каждой оси сосед +1 раньше −1, по диагонали — когда спускаются обе оси) |
| Спавн | только точки `S` (8). До 4 равновероятных попыток точки не ближе `spawn_min_distance`, иначе самая дальняя (первая при равенстве); затем сдвиг до cell/2 − тело по x, потом по y из того же потока RNG |
| Выстрелы | снаряды героя и врагов гаснут в твёрдых клетках и пролетают над `w` |
| Расталкивание | обход только занятых клеток сетки (ключи «клетка × 8192 + слот», сортировка). Совпадает с полным обходом: digest всех прежних трасс без арены не изменился |

**Отличие от §4.3.** Враги не появляются у входов `E`: на доске REF-033 входы — места старта героя, и спавн там ставил бы врагов на игрока.

### 8.3. Паритет и тесты

- Python-эталон (`sim_core.py`) повторяет арену бит в бит. Новые трассы:
  - `arena_hero_walls` — герой обходит стены по 8 направлениям;
  - `arena_w0_hero_stands_still`, `arena_w0_into_court`;
  - `arena_windows_compressed`;
  - `arena_stress_150_attacks`.
- GUT воспроизводит все трассы и журналы ботов с тем же digest и проверяет digest сетки в конфиге.
- Инварианты на всех трассах арены: ни одно тело не стоит в стене, ни один снаряд не живёт в твёрдой клетке.
- Сцена:
  - пол по всем непустым клеткам;
  - обрывы под краями у пустоты, водопады;
  - печать в центральной клетке, золотые линии до первой стены;
  - реквизит из файла на своих клетках;
  - остальные стены — временные каменные блоки до среза А2.

### 8.4. Боты (перепривязка)

Kiter видит клетки арены и центр печати. Он отталкивается от твёрдых клеток ближе 2 клеток, без угрозы идёт по полю потока к печати и держит направление, пока оно не хуже 3/4 лучшего. Решение — каждые 12 тиков. Лимит команд якорей поднят с 700 до 2000 (kiter у стен меняет направление ~1200 раз), файл прогонов — до 256 КиБ.

| Бот (32 seed, медиана смерти) | До А1 | А1 |
|---|---|---|
| стоит | 28 с | 100 с |
| по кругу | 53 с | 78 с |
| kiter | 84 с | 249 с, доживают 4/32 |
| `kiter_upgrades` (доживают) | 32/32 | 32/32 |
| `diag_first_id` / `diag_utility_first` | 18/32 / 0/32 | 21/32 / 5/32 |

Коридоры пересчитаны по прежнему правилу (выживший считается как 18000 тиков). Порядок «стоит < по кругу» снят: «по кругу» уходит с западной площадки на мост навстречу орде. Закрепление исходов среза 4 (`SLICE4_ANCHORS`) снято: арена меняет все прогоны.

### 8.5. Производительность и последствия

- **Стресс 150 врагов** (headless, Windows, 3000 тиков, одна машина в один день):

  | Сценарий | main | А1 |
  |---|---|---|
  | без арены, p95 тика | 4,23 мс | 4,26 мс, digest тот же |
  | все атаки, p95 тика | 3,6 мс (прямоугольник) | 4,7 мс (арена) |

  BFS поля — около 0,7 мс на смену клетки героя. В тот день машина была медленнее эталонного замера (main без арены — 4,2 мс против прежних 2,1–2,7), поэтому сравнивать надо относительно: арена добавляет около 30 % (≈ 2,5 мс на эталонном масштабе, лимит 4 мс). Пересчёт поля по частям не понадобился.
- **Сложность упала.** Старт за мостом — узкое место: враги идут к герою по одному пути, а поле в 3,4 раза больше. Темп спавна и лимиты угроз не менялись (§4.7). Новый темп и, при необходимости, спавн ближе к старту — отдельное решение после плейтеста.
- **Камера** по-прежнему держит героя внутри рамки с отступом 4 клетки.

## 9. Стражи двора (2026-11-16)

Старый лев (104 px на экране, рост героя 84 px) читался серой фигуркой, а не храмовым стражем REF-033/029. Его и столб заменил отдельный атлас — первая деталь набора А2 (§5).

- **`asset.prop.courtyard_guardians`** через утверждённый imagegen с досками REF-033 и REF-029 (`art_source/courtyard_guardians/`):
  - лев с шаром и лев с детёнышем на ступенчатых резных постаментах;
  - столб с красной лакированной панелью и золотым медальоном;
  - сломанный столб (в запасе для обломков А2).
- **Проекция.** Генератор тянет квадратное основание к виду спереди (одна широкая грань). На полу 2:1 такое основание не лежит в плоскости карты. Первая версия атласа так и вышла, наклон нижних рёбер 0,26 / 0,42 вместо 0,5. Поэтому лист рисуется поверх шаблона геометрии [`tools/art/iso_template.py`](../../tools/art/iso_template.py):
  - серые соосные блоки на хромакее;
  - основание углом к зрителю, верх — ромб 2:1;
  - обе грани равны, свет слева.

  Шаблон — первое приложенное изображение промпта.
- **Посадка в клетки.** Каждый лев и столб из файла арены стоит на квадрате 2 × 2 твёрдых клетки (96 px мира, ромб шириной 136 px на экране). Высота спрайта подобрана так:
  - основание льва закрывает 95 % ширины ромба;
  - столб высотой 3 роста героя (§5: 2–3) закрывает 74 %.
- **Высоты на экране:** лев с постаментом 212 px (≈ 2,5 роста героя, сама фигура ≈ 1,3 — в коридоре §5), столб 250 px (≈ 3,0).
- **Проверки:**
  - `test_guardian_bases_lie_on_the_floor` (GUT) меряет по альфе атласа медианный наклон нижнего контура (0,5 ± 0,06 с обеих сторон) и ширину основания (лев 0,85–1,05 ромба, столб 0,65–1,0);
  - `test_guardians_tower_over_the_hero` держит высоты;
  - `tests/test_iso_template.py` — сам шаблон.
  - `tools/art/measure_base.py` — тот же замер наклона по мастеру до сборки (код выхода 1 — перегенерировать); его тест `tests/test_measure_base.py` на stdlib.
- **Расстановка:** `ArenaDressing.PROP_SPRITES`. Львы из файла арены стоят парами: первый с шаром, второй с детёнышем и отзеркален. Лев из `courtyard_lights` и колонны из `courtyard_nature` в сцене больше не рисуются; атласы не пересобирались.
- **LFS:** +1,9 MiB, остаток бюджета ≈ 2,2 MiB.
- **Для всех деталей А2:** лист по шаблону проекции, затем `measure_base`, проверка посадки и кадр в игре рядом с доской (скилл `hip-art-asset`).
- **Следующее улучшение:** у всех пропов нормали — «подушка» от силуэта (скос 14 px), гранёные постаменты из-за этого скругляются. Шаблон знает точные грани и может дать им плоские нормали. Это отдельная задача, свет нужно проверять в игре.

## 10. Балюстрада по клеткам `w` (2026-11-17, А2a)

Низкие стены (`w`) рисовались серыми кубиками-заглушками. Теперь это балюстрада REF-029: каменные столбики с золотыми навершиями, между ними красные лакированные перила на каменном бордюре.

- **`asset.prop.courtyard_balustrade`** через утверждённый imagegen с REF-029 (фрагмент балюстрад и арены набора) и REF-033 (`art_source/courtyard_balustrade/`):
  - столбик (`post`, 66 px, 0,79 роста героя);
  - сломанный столбик (`post_broken`, 38 px, ниже перил);
  - груда руин на клетке (`rubble`, 39 px);
  - фронтальная развёртка одного пролёта перил (`rail`, 42 px, 0,5 роста героя).
- **Лист по шаблону** `iso_template.py courtyard_balustrade`. В шаблоне появился плоский прямоугольник `flat` — развёртка пролёта: её рисуют спереди, без изометрии.
- **Выбор кандидата.** Из двух листов взят второй. Наклон оснований по `measure_base`: столбик +0,465 / −0,486, сломанный +0,468 / −0,489. У первого листа осколки у ног сломанного столбика в игровом масштабе занимают половину стороны основания, и тест по атласу давал −0,28.
- **Перила — плоскость, а не спрайт.** Пролёт натягивается на вертикальную плоскость между центрами двух соседних столбиков и обрезается по их граням (`ArenaDressing.draw_rail`, `rail_quads`). Пролётов на участке столько, сколько целых развёрток помещается в его длину. Так геометрия точна по построению: основание перил лежит на линии между столбиками.
- **Сетка.** `ArenaDressing.balustrade(rows)`:

  | Правило | Как сделано |
  |---|---|
  | Связи | соседи по осям и диагоналям; диагональ не связывается, если две клетки уже соединены через угловую клетку — «лесенка» на сетке даёт один прямой отрезок |
  | Отрезки | 4 направления: по оси сетки (на экране 2:1) — столбик через клетку; по диагонали клеток поперёк экрана — на каждой клетке (68 px); вверх по экрану — через клетку, перила не рисуются (торец, `edge_on`) |
  | Тупики | конец линии с одной связью — сломанный столбик |
  | Руины | клетки внутри квадрата 2 × 2 из `w` — груда, зеркальная груда или сломанный столбик по хэшу клетки (половина — столбики) |
  | Без атласа | клетки `w` остаются блоками, как раньше |

- **`measure_base` уточнён.** Медиана шагов в четверть стороны квантует наклон до 1/шаг. На основании столбика (шаг 16 px) ошибка в 1 px давала 0,438 при допуске 0,06. Теперь медиана задаёт только начальную прямую, а колонки в полосе ±2,5 px от неё дважды уточняются наименьшими квадратами. Листья и осколки в подгонку не попадают. Тот же расчёт — в GUT (`_median_slope`). Прежние листы стражей меряются так же: годные ≈ 0,50, бракованный лист львов 0,40.
- **Проверки (GUT `test_arena_dressing.gd`):**
  - каждая клетка `w` — столбик, клетка пролёта или руина; ни одного блока на `w`;
  - лесенка — один отрезок; через клетку по оси; Г-образный угол — через угол;
  - перила идут от центра столбика и стоят вертикальной плоскостью на этой линии;
  - высоты к герою;
  - основания столбиков на полу 2:1 по альфе атласа; основание в виде спереди (0,26) тот же замер бракует;
  - руины используют все три вида.
- **LFS:** +1,0 MiB (мастер без потерь), остаток бюджета ≈ 1,1 MiB.
- **Не сделано:**
  - у перил нет отбрасываемой тени (тень пропа строится от точки основания, а у перил основание — линия);
  - груда руин одна на атлас, и в квадрате руин она повторяется. Нужен лист из 3–4 вариантов, а по бюджету — мастер с потерями (WebP q92, ≈ 0,12 MiB против 1,0);
  - твёрдые клетки `#` без именованного пропа — по-прежнему тёмные блоки: подпорная стена, зал ворот, лестницы и мост — следующие детали А2.
