## 1. Исходные данные и их достоверность

**Метод.** 2026-11-19 восемь независимых исследований (Gemini 3.8 Flash High через Antigravity CLI, веб-поиск): (1) game feel и читаемость; (2) билды и драфт; (3) враги, волны, темп; (4) мета-прогрессия; (5) онбординг, UX, доступность; (6) производительность Godot 4.5–4.7; (7) плейтест, баланс, телеметрия; (8) арт/аудио-пайплайн и ИИ-ассеты.

**Проверка источников.** Из 143 процитированных URL ответили HTTP 200 только 83, причём значительная часть — главные страницы сайтов, а не статьи. В темах «билды», «мета-прогрессия», «доступность» большинство глубоких ссылок — 404 (ссылки сгенерированы). Сырые ответы поэтому **не** кладутся в репозиторий как evidence.

**Правило применения.** Рекомендация попадает в план, только если (а) повторяется в нескольких независимых ответах **и** (б) согласуется с уже действующими документами проекта или проверяется нашими тестами/плейтестом. Конкретные числа из исследований (длительности, пороги, проценты) — **гипотезы для проверки**, а не нормы. Юридические и платформенные утверждения (правила Steam об ИИ, судебные решения) — не проверены; перед решениями — первоисточник (§4, D9).

Ссылки, ответившие 200 и относящиеся к делу (содержимое сверить при использовании): [Steam Deck compat](https://partner.steamgames.com/doc/steamdeck/compat), [Steam Deck recommendations](https://partner.steamgames.com/doc/steamdeck/recommendations), [Steamworks privacy](https://partner.steamgames.com/doc/features/privacy), [Godot GUI navigation](https://docs.godotengine.org/en/stable/tutorials/ui/gui_navigation.html), [Game Accessibility Guidelines](https://gameaccessibilityguidelines.com/), [PostHog Godot](https://posthog.com/docs/libraries/godot) — все проверены 2026-11-19.

## 3. Принципы исполнения

1. **View не пишет в симуляцию.** Каждый срез слоя представления доказывает, что digest бот-replay и `RunView` не изменился (`test_sim_bots`, `test_run_view`).
2. **Изменения симуляции — только через ADR** + Python-оракул `tools/content/sim_core.py` + GUT-паритет + перегенерация фикстур ботов. Такие срезы не отдаются исполнителю без точной спецификации всех чисел.
3. **Настройки не трогают danger-layer** (G3): ни один ползунок не скрывает телеграф и угрозу; `own_skill_opacity` действует только на эффекты героя.
4. **Один источник настроек:** схема `SETTINGS_SCHEMA` + `.work/config/v7/settings.example.cfg`; рантайм читает те же ключи из `user://settings.cfg`. Новые ключи сначала в схему и валидатор.
5. **Все числа задаёт спецификация**; исполнитель не придумывает значения, digest и векторы.
6. **RU/EN** для каждой новой строки — через `game/content/locale/strings.json` и проверку `tests/test_ui_strings.py`.
7. **Капчеры и эталонные кадры** (`game/tools/capture_*.gd`) запускаются с `screenshake = 0` и без чисел урона, чтобы сравнения кадров оставались стабильными.

## 5. Карточки задач для исполнителя (волны 1–3)

Общие для всех карточек: работа в отдельном worktree от `origin/main`; разрешены только перечисленные файлы; без новых зависимостей; все строки RU/EN; проверки §7. Числа ниже — **предложения плана**, утверждаются при приёмке среза (значения по умолчанию — вопрос В1, §8).

### Q1 — рантайм-настройки

- **Goal:** `PresentationSettings` (RefCounted) читает и пишет `user://settings.cfg` (ConfigFile), отдаёт значения с ограничением диапазона, при отсутствии/порче файла — значения по умолчанию.
- **Схема (расширение `SETTINGS_SCHEMA` и `settings.example.cfg`):** `[graphics]` `screenshake` unit = 0.40 (есть), `vfx_intensity` unit = 0.65 (есть), `hit_flash` unit = 1.0, `own_skill_opacity` unit = 0.8 (в рантайме не ниже 0.2), `floating_damage_numbers` enum `off|aggregate|all` = `aggregate`; `[playtest]` `log_choices` bool = false (новый тип `bool` в валидаторе).
- **Files:** `scripts/validate_content.py`, `.work/config/v7/settings.example.cfg`, `game/presentation/settings/presentation_settings.gd`, `game/tests/unit/test_presentation_settings.gd`, `tests/` (тест валидатора).
- **Acceptance:** roundtrip; неизвестный ключ игнорируется; значение вне диапазона ограничивается; битый файл → умолчания; валидатор отвергает неизвестный ключ и неверный enum (отрицательные тесты).

### Q2 — тряска камеры

- **Goal:** `CameraShake` (RefCounted): `trauma ∈ [0, 1]`; события: урон герою +0.30, смерть героя +0.60; добавления чаще 0,05 с игнорируются; затухание 1,6/с; смещение `Camera2D.offset = 8 px × screenshake × trauma² × шум(t)` (шум детерминирован от времени кадра, не от RNG симуляции).
- **Files:** `game/presentation/run/camera_shake.gd`, `run_view.gd` (только подключение), тест.
- **Acceptance:** при `screenshake = 0` смещение ровно 0; после последнего события смещение 0 не позже чем через 1/1.6 с; `trauma` не превышает 1; digest replay `RunView` не меняется.

### Q3 — вспышка при попадании

- **Goal:** в `EnemyReactions` новая вспышка врага начинается не чаще раза в 0,1 с на uid; сила вспышки × `hit_flash`.
- **Files:** `enemy_reactions.gd`, `run_view.gd` (передача настройки), тест.
- **Acceptance:** поток ударов каждые 0,02 с даёт ≤ 1 старт вспышки за 0,1 с; `hit_flash = 0` → вспышки нет, отброс и клип удара сохраняются.

### Q4 — числа урона

- **Goal:** `DamageNumbers` (RefCounted, отрисовка в своём проходе без нод на число) по событиям `strikes` = [позиция px, урон в milli-HP, uid, killed] из `FixedTickDriver.take_events()`.
- **Правила:** `aggregate` — сумма по uid в окне 0,12 с, одно число в последней позиции; `all` — число на каждый удар; `off` — ничего. Показ `max(1, (milli + 500) / 1000)` HP; подъём 20 px за 0,7 с, затухание последние 0,3 с; не больше 48 чисел, при переполнении заменяется самое старое; добивающий удар — крупнее на 25 %.
- **Files:** `game/presentation/run/damage_numbers.gd`, подключение в `run_view.gd`, тест.
- **Acceptance:** 10 ударов по одному uid за 0,1 с в `aggregate` → одно число с суммой; лимит 48; `off` → пусто; digest не меняется.

### Q5 — прозрачность своих эффектов

- **Goal:** `own_skill_opacity` умножает альфу снарядов и эффектов героя (включая проходы `run_effects_passes.gd`); проходы угроз (`_danger`, телеграфы, снаряды и зоны врагов) не меняются.
- **Acceptance:** при 0.2 альфа эффектов героя × 0.2, цвета телеграфов и зон врагов — без изменений (тест сравнивает константы/модуляцию проходов).

### Q6 — пауза и настройки

- **Goal:** `ui_cancel`/Start открывает паузу поверх забега (симуляция стоит на границе тика, как при выборе), в ней — 5 элементов настроек из Q1 и «Продолжить»; фокус геймпада по кругу, без ловушек фокуса; сохранение при закрытии; RU/EN ключи `SETTINGS_*`.
- **Acceptance:** открытие/закрытие паузы не меняет digest; навигация стрелками и D-pad проходит все элементы; ключи есть в обоих языках; кадр 1280×800 снят для проверки U4.

### B1 — балансный прогон

- **Goal:** `tools/content/balance_survey.py --jobs N --seeds 101..132 --out .tools/balance` по образцу `arena_opening_probe.py`: класс × бот × seed → JSON/CSV: победа, тик смерти, убийства, уровень, `hp_min`, выборы; по каждой карте — сколько раз показана, взята, доля побед при взятой.
- **Choosers:** кроме существующих — `seeded_random` (выбор детерминирован от seed забега и номера руки) только внутри инструмента; фикстуры ботов и `BOT_POLICY_VERSION` не меняются.
- **Acceptance:** два запуска дают побайтно одинаковый вывод; строка `kiter`/seed 101 совпадает с `survey` в `sim_bot_runs.json`; unittest на агрегацию по картам.

### B2 — журнал выбора

- **Goal:** при `[playtest] log_choices = true` меню выбора дописывает строку JSON в `user://playtest/choices.jsonl`: run uid, тик, показанные ID, взятый ID, миллисекунды от открытия до выбора. По умолчанию выключено; ничего не отправляется по сети.
- **Acceptance:** выключено → файла нет; включено → одна строка на выбор; digest не меняется.

### A1 — звуковой каркас

- **Goal:** `AudioDirector` (только View): шины `Master/Music/SFX/UI` в `default_bus_layout.tres`; плеер на каждый ID звука с `max_polyphony = 4`; при старте телеграфа SFX приглушается на −5 дБ на 0,3 с; громкости — новые ключи `[audio]` в схеме Q1.
- **Acceptance:** тест: пятый одновременный запуск того же ID не увеличивает число голосов; приглушение возвращается к 0 дБ; без ассетов — тихие заглушки, решение A0 подставляет реальные.

## 6. Что исполнителю не отдаётся
