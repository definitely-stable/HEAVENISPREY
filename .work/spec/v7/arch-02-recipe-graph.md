## 1. Что решает

Для каждой пары «профиль забега × рецепт» модель выдаёт **либо** witness — путь из пиков драфта и событий наград, который независимый replay проигрывает от стартового билда, с минимальным числом пиков и самой ранней секундой, — **либо** одну объяснимую причину недостижимости. «Недостижим, потому что не нашли» не принимается: модель падает с ошибкой.

| Вердикт | Значение | Рычаг дизайна (не ограничение движка) |
|---|---|---|
| `REACHABLE` | witness + picks + second | — |
| `RANK_UNREACHABLE` | требуемый ранг > `max_rank` + объявленный post-max рост | Limit Break / repeatable growth |
| `NO_SOURCE` | у входа нет источника и ни один рецепт его не выдаёт | источник в драфте, событии, рецепте |
| `CLASS_LOCKED` | входы доступны только другим классам | class allowlist, стартовая техника |
| `CAPACITY` | путь есть только при большем числе одновременных слотов | ёмкость профиля, Meridian, слот из события |
| `GATE_EXHAUSTED` | нужно больше событий-наград (ритуал, прорыв, реликвия), чем даёт забег | частота событий |
| `PICK_BUDGET` | пиков драфта за забег не хватает (или позже конца забега) | XP-кривая, длительность, источники |

Причины могут сочетаться (`CAPACITY+GATE_EXHAUSTED`). Rarity меняет шанс, а не возможность, поэтому во входы достижимости не входит; ожидаемое время с учётом весов — задача DraftService (ARCH-03).

## 2. Модель

- **Состояние:** активные/пассивные `{id: rank}`, дары, бонусы ёмкости, счётчики событий; профиль задаёт класс и базовую ёмкость.
- **Действия:** `acquire` (1 пик, источник `draft`, класс, свободный слот), `rank` (1 пик, до `max_rank + growth_steps`), `recipe` (0 пиков, одно использование события-ворот).
- **Трансформация** проверяется целиком до применения: входы и ранги, свободное событие, **занятость после всех выходов N→M** (выдача пассивки при полном пассивном ряду — отказ), отсутствие дубля выдачи.
- **Поиск:** кратчайший путь 0-1 по пикам над обратным замыканием целевого рецепта (только релевантные входы и ранги, плюс рецепты ёмкости), поэтому пространство состояний конечно и мало. Время: `max(time_for(picks), first_second использованных ворот)` по гипотетическому расписанию пиков.
- **Replay:** каждый witness заново проигрывается с полной валидацией; изменённый путь (выброшен ранг) отклоняется.

## 3. Статические правила

1. Виды: `EVOLUTION` (ровно 1 вход), `UNION` (≥2), `GIFT` (без поглощения, только дары), `MUTATION` (≥1, может вести к драфтовой форме), `MERIDIAN` (только ёмкость). Результат EVOLUTION/UNION не продаётся в драфте.
2. Рецепты, поглощающие общий вход, обязаны иметь общий `exclusive_group`: одновременно применимые показываются игроку вместе и никогда не выбираются по порядку JSON (BLD-08).
3. **Циклы трансформаций** (например Инь ↔ Ян) разрешены только явно (`allow_cycle`) — конечность гарантируют конечные события-ворота (`max_per_run`), поэтому число трансформаций за забег ≤ Σ `max_per_run`.
4. **Рост после max rank:** `limit_break.max_steps` или `repeatable` с обязательным `value_cap` — конфигурируемо большой предел, а не бесконечный счётчик (FLEXIBILITY §1).
5. Многоуровневые цепочки base → evolved → union → gift выражаются без особых случаев: входом может быть результат другого рецепта.

## 4. Golden witness (фикстура)

`sample.recipe.sky_tribute` в профиле standard: `sword_rain` (EVOLUTION) → `storm_sword` (UNION из эволюции) → `heaven_prison` (UNION N→M: активка + пассивка) → GIFT. 11 пиков, секунда 270 (реликвия босса). В профиле minimalist (1 активный слот + Meridian) та же цепочка упирается в `CAPACITY` из-за второго выхода N→M в пассивный ряд, а `storm_sword` достижим только через Meridian. 26 ожиданий по трём профилям, все witness проиграны заново.

## 5. Чего это не доказывает

Вероятность или ожидаемое время получения рецепта при весах драфта (ARCH-03), удовольствие от выбора, баланс силы, дубли экземпляров (BLD-22), runtime-транзакции в Godot (GAP-PY-GD-PARITY). Реальные XP-кривая и частота ритуалов — product-вопросы.
