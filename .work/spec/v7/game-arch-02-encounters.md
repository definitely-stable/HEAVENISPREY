## 1. Арена (`StageTopologyDef`)

Ручная сетка 32×20 для `stage.jade_grove`: стены, мягкий кустарник (замедление 0.72), полосы спавна по краю, круг арены босса, стартовая клетка. Процедурная генерация не требуется: размеченная арена проще проверяется.

| Правило | Код ошибки |
|---|---|
| Все проходимые клетки связаны со стартом, нет изолированных карманов | `E_ISOLATED_POCKET` |
| Нет коридоров шириной 1 длиннее `max_corridor_length` (ловушка при окружении) | `E_TRAP_CORRIDOR` |
| Для **любой** позиции игрока есть полоса спавна не ближе `min_spawn_distance_cells` | `E_SPAWN` |
| Внутри круга арены босса нет твёрдых клеток (нет неустранимых блокеров пути) | `E_ARENA_BLOCKER` |
| POI (алтари) достижимы из худшей клетки за долю окна, и путь плюс ченнелинг укладываются в окно | `E_POI`, `E_POI_REACH` |

## 2. Телеграфы и уход от опасности (канонические атаки)

Для всех 14 атак v7: контактные — интервал удара ≥ `min_contact_interval_ticks`; остальные — `telegraph ≥ min_telegraph_ticks`, окно восстановления у дуг/рывков/снарядов, рывок не перенацеливается, снаряд не самонаводится и фиксирует цель в конце телеграфа. **Маршрут ухода:** `скорость × telegraph ≥ дистанция выхода` (радиус дуги/зоны, полуширина полосы рывка, шаг в сторону от снаряда).

**MIXED:** если в окне ростера есть атака, накладывающая `status.root_slow`, бюджет всех атак этого окна умножается на канонический `movement_speed_multiplier` (0.72). В `jade_grove.w3` минимальный запас — 0.256 клетки у `jade_stomp`.

**Находка для дизайн-ревью (не изменение канона):** при гипотетической скорости 0.1 клетки/тик у `enemy_attack.snake_bite` запас ухода ровно 0 (20 тиков телеграфа × 0.1 = 2 клетки = радиус). Любое замедление или скорость ниже 0.1 делает укус неизбежным. Решение — после реальной скорости игрока в P0: либо телеграф ≥ 24, либо радиус меньше; в каноне ничего не меняется без согласования.

## 3. Волны (`EncounterDef`)

Окна ростера непрерывно покрывают 0–300 с; у каждой атаки окна есть управляющий `threat_cap` (снаряды, рывки, зоны контроля, посмертные зоны). Таймлайн: элита 120 с, носитель сундука 150 с, элита 205 с, вход босса 270 с; между пиками ≥ `spike_min_gap_seconds` (окно восстановления). Алтари ритуала открываются в 90, 170 и 240 с.

## 4. Паттерн босса (`BossPatternDef`, `boss.jade_warden`)

- Фазы 100→60→25→0 по HP без разрывов; переход ≤ `max_transition_ticks`, без атак.
- Атаки: удар по кругу, кольцо корней, рывок по линии к игроку (aim lock в конце телеграфа), призыв канонических `enemy.yin_corpse`. Телеграф ≥ 30 тиков, у каждой есть восстановление.
- **Наложения** активных окон в ротации обязаны быть объявлены (`E_UNDECLARED_OVERLAP`); для каждой одиночной атаки и каждого объявленного наложения проверяется, что из **любой** клетки арены достижима безопасная клетка за минимальный телеграф (поиск по сетке с ценой кустарника).
- В каждой ротации есть пауза без опасности ≥ `min_punish_ticks` (с учётом цикла) — окно наказания и передышки.
- Нет иммунитета к целому origin урона (`dot`, `zone`, `summon`, `proc`… из [ARCH-04](arch-04-effect-chains.md)); сопротивление контролю обязано иметь fallback. Так ни одно семейство билдов не выключается боссом.

## 5. Источники специальных наград и порядок событий

Источники: 3 алтаря (`RITUAL`, по завершению ченнелинга), сундук носителя (`CHEST`, по подбору дропа с убитого носителя), реликвия босса (`BOSS_RELIC`, по смерти босса). `reward_event_id = source:run_uid:instance`.

- События дедуплицируются по `uid` (повтор идемпотентен, тот же uid с другим содержимым — `E_EVENT_CONFLICT`) и сортируются по `(tick, фаза, uid)`. Фазы: `combat → death → drop → pickup → poi → progression` — версия предложения для OPEN RLOOP-01, не принятое правило.
- Каждая выдача проверяет ворота: подбор только дропа с мёртвого носителя, ченнелинг только на открытом и не истёкшем алтаре и не короче `channel_ticks`, смерть босса не раньше входа, однократность.
- Golden-лог из 13 событий даёт 5 наград и очередь выбора `RITUAL, LEVEL_UP, CHEST, LEVEL_UP, RITUAL, BOSS_RELIC, RITUAL, LEVEL_UP` при любом порядке поступления.
- **Согласованность с ARCH-02:** арена даёт ровно столько событий `RITUAL`/`BOSS_RELIC`, сколько предполагает граф рецептов, и не раньше (`E_GATE_BUDGET`).

## 6. Чего это не доказывает

Реальный pathfinding и навигацию толпы, честность при 100+ врагах на экране, читаемость телеграфов, реальную скорость и хитбоксы игрока, баланс HP босса, смерть игрока в тот же тик (GAP-PRECEDENCE, GAME-ARCH-05). Это сетевая модель с гипотетическими константами; финальная проверка — bot-сценарии ROOT-ESCAPE/RANGED-DODGE/MIXED в игре.
